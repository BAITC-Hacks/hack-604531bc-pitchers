# pITchers: умный подбор подрядчиков

HackAlem AI, трек «Креативные индустрии», кейс #79-lite.

Заказчик уже выбрал город и формат мероприятия, но в каталоге слишком много вариантов. Сервис принимает параметры заказа, выбирает до трёх доступных подрядчиков и объясняет каждый выбор конкретными фактами. Ценность решения: сократить время выбора, показать различия кандидатов и понятные причины пустой выдачи.

## Что реализовано

- Загрузка 66 профилей из CSV в память, нормализация цен, форматов, языков, календарей и флагов.
- Детерминированные фильтры и ранжирование; занятые на выбранную дату профили исключаются.
- Статусы `found` (3 карточки), `partial` (1–2), `no_category`, `all_filtered`; причины отсева, другие города, подсказки по дате и бюджету.
- `explain(result)`: один запрос к LLM для всех карточек, 1–2 предложения на русском из фактов движка; одна перегенерация при невалидном ответе.
- Общий предел AI 8 секунд, внешний предел сервера 9 секунд, файловый кэш только проверенных LLM-ответов. Шаблоны не кэшируются.
- Адаптивный интерфейс с формой, тремя демо-кнопками, четырьмя исходами подбора, причинами отсева и применяемыми подсказками по дате, городу и бюджету.
- Избранное в браузере, подробный профиль, скачивание JSON, обработка загрузки и сетевых ошибок.
- Скрытие имён для слепого сравнения; ввод события свободным текстом через `/api/parse` при настроенном LLM. При недоступном распознавании ручная форма остаётся рабочей.
- Автоматические тесты ядра, HTTP, браузера и консольная демонстрация для жюри.

Готовы ядро, AI-модуль, HTTP-сервер и интерфейс `public/`. `npm start` запускает сайт на `http://localhost:3000` (порт задаётся через `PORT`). Для просмотра без внешних API: `npm run preview`; если порт занят, выбирается следующий свободный. Публичного развёртывания нет: localhost доступен только на вашем компьютере.

## Быстрый запуск сайта

```powershell
npm ci
npm run preview
```

Откройте адрес, напечатанный в терминале. Сразу появится подборка из реального каталога.
Для LLM-режима настройте собственный `.env`, прогрейте кэш и выполните `npm start`.
Режим `preview` явно отключает внешние вызовы только внутри процесса, не изменяя `.env`.
Карточки показывают источник объяснений; работающий сайт не означает, что доступ к LLM уже подтверждён.

## Сценарий и архитектура

Вход: `city`, `date` (YYYY-MM-DD), `eventType`, `category`, `budget`; опционально `hours` и `language`. Даты допустимы только с `2026-09-23` по `2026-12-31`.

```text
CSV -> нормализация -> город/категория -> жёсткие фильтры
    -> детерминированные баллы -> первые 3 + факты
    -> кэш / LLM с таймаутом / резервные объяснения -> EngineResult
```

Фильтры идут в порядке: занятость, бюджет, формат, язык, часы. Каждый исключённый профиль учитывается по первой причине. Ранжирование: релевантность описания 35%, запас бюджета 25%, специализация 15%, часы 15%, качество данных 10%. Балл округляется до четырёх знаков; при равенстве порядок определяется `id`.

Выход сохраняет `EngineResult`: `status`, `query`, `candidatesTotal`, `excluded`, `excludedList`, `cards`, `commonFacts`, `otherCities`, `hints`, `actions`, `message`. AI добавляет карточкам `explanation` и `explanationSource`: `llm`, `template` или `cache`. Общие факты движка передаются массивом строк `commonFacts` и показываются над карточками. Имена, цены, баллы, `factChips`, сообщения и порядок не меняются.

LLM получает запрос, ID и факты карточек, общий контекст и отличия, вычисленные из этих фактов. Имена и баллы не передаются. Каждое объяснение начинается с отличия: например, лимита часов или цитаты из описания. Попарно проверяется, что у каждой карточки есть собственная цифра или цитата, отсутствующая у другой. Если факты совпадают, модуль не выдумывает уникальность.

Проверяются JSON, точное множество ID, длина, числовые факты, цена, обязательные детали, попарная различимость и маркировка синтетики/оценочных цен. Общие дата и формат не повторяются в объяснениях. Невалидный ответ получает одну повторную попытку в пределах тех же 8 секунд, затем локальный резерв. Это не полная семантическая проверка каждого слова модели.

Ключ кэша: SHA-256 от версии, JSON запроса, упорядоченных ID и модели; порядок ключей нормализуется. Отдельный отпечаток фактов, endpoint и промпта защищает от устаревших текстов. Сохраняются только проверенные ответы с `source: "llm"`. После временного шаблона следующий запрос снова пробует модель. Одновременные одинаковые запросы используют общий вызов LLM.

Node.js 24, ES modules, Express, `csv-parse`, `dotenv`, SDK `openai`; интерфейс на HTML/CSS/vanilla JS с локальными иконками Lucide. Тесты: `node:test` и Playwright. Сборка фронтенда, база данных и дообучение не нужны.

## Установка

Откройте репозиторий в VS Code и выполните в терминале:

```powershell
node --version
npm ci
node src/engine/data.js
```

Для офлайн-демо ключ не нужен. Для LLM создайте личный `.env` в корне:

```dotenv
LLM_API_KEY=your-own-key
LLM_BASE_URL=
LLM_MODEL=gpt-4o-mini
PORT=3000
```

Выберите модель, доступную в своём аккаунте. `LLM_BASE_URL` пуст для стандартного OpenAI API; для NVIDIA по командной конфигурации: `https://integrate.api.nvidia.com/v1`. При смене провайдера нужны его ключ и модель с поддержкой Chat Completions, JSON-ответов и `temperature=0`. Работоспособность конкретной NVIDIA-модели отдельно не подтверждена.

Поддержаны резервные имена `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`, если `LLM_*` не заданы. Само наличие `NVIDIA_API_KEY` не переключает провайдера. Ключ используется приложением; расширение VS Code для API не требуется. `.env`, `node_modules` и `.cache` не коммитятся.

Официальная справка: [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [JSON-ответы](https://developers.openai.com/api/docs/guides/structured-outputs).

## Проверка для жюри

```powershell
npm test
npm run test:ui
node src/ai/verify.js
node src/ai/demo.js
npm run demo
```

Тесты работают без внешних вызовов. Playwright на Windows использует установленный Edge; иначе установите Chromium командой `npx playwright install chromium`. Проверяются реальные HTTP-запросы, разные даты, отсутствие категории, подсказки, профиль, избранное после перезагрузки, экспорт, ошибки сети и экран шириной 320 px. Скриншоты: `.cache/screenshots/`.

`verify.js` запускает HTTP-сервер на свободном порту, проверяет метаданные, пять сценариев, `commonFacts`, сохранение полей движка, повторяемость и HTTP 400, затем закрывает сервер. Ключи отключены только в процессе проверки, `.env` не меняется. `npm run demo` запускает командное демо движка.

| Сценарий | Город, категория, дата | Формат и бюджет |
| --- | --- | --- |
| Плотная категория | Алматы, Ведущий, 17.10.2026 | корпоратив, 1 500 000 ₸ |
| Другая дата | Алматы, Ведущий, 26.12.2026 | корпоратив, 1 500 000 ₸ |

`src/ai/demo.js` повторяет каждый запрос и проверяет совпадение ID и текстов. Тесты дополнительно проверяют различимость объяснений после удаления имён, занятость, флаги, сохранение полей движка, единый LLM-вызов, таймаут с отменой, повреждённый кэш, ошибки API и повторяемость после создания нового экземпляра.

Реальный вызов настроенного провайдера:

```powershell
node src/ai/warm-cache.js --refresh
node src/ai/warm-cache.js --check
node scripts/blind-test.js --live
```

Прогрев проверяет пять сценариев: три с LLM-карточками и два пустых, где модель не нужна. Новый читатель с отключённым API проверяет сохранение текстов на диске. При шаблоне или ошибке записи скрипт завершится с кодом 1. `--check` не обращается к сети. После успешного прогрева перезапустите сервер. Подробнее: [подготовка AI-демо](src/ai/README.md).

`explanationSource: llm` означает принятый ответ модели, `template` означает резерв, `cache` означает сохранённый LLM-ответ, никогда шаблон. Офлайн-проверка без имён: `node scripts/blind-test.js`. Успешная выдача карточек сама по себе не подтверждает подключение LLM.

## Подключение к серверу

Сервер уже подключает модуль объяснений. Основной вызов:

```js
import { recommend } from "./engine/recommend.js";
import { explain } from "./ai/explain.js";

const query = {
  city: "Алматы", date: "2026-10-17", eventType: "корпоратив",
  category: "Ведущий", budget: 1500000,
};
const result = await explain(recommend(query));
```

Сервер отвечает за HTTP-ошибки и `elapsedMs`, передаёт `commonFacts`, а в случае сбоя использует общие AI-шаблоны. AI не меняет `message` и статусы. Для тестов доступны `createExplainer({ client, cache, timeoutMs, onFallback })` и `createCache({ filePath })`. Общий таймаут AI 8 секунд, внешний серверный предел 9 секунд. `GET /api/meta` дополнительно возвращает `catalogue.total`.

Подключены командные маршруты `GET /api/selfcheck` (отчёт десяти проверок), `POST /api/compare` (сравнение дат, тело `{ query, date2 }`) и `POST /api/parse` (распознавание текста). Результат распознавания заполняет форму, но не запускает подбор до подтверждения пользователем.

## Показ и сдача

1. Запустить `node src/ai/verify.js` и убедиться, что все проверки завершились с `OK`.
2. Запустить `npm run preview` или, после успешного прогрева LLM, `npm start`. Показать на сайте три карточки осенью, одну 26 декабря, редкую категорию и пустую выдачу с применением подсказки.
3. Обратить внимание на разные детали карточек, цифры причин отсева и маркировку синтетического флориста. Повтор каждого запроса уже проверяется в демонстрации.
4. Передать жюри ссылку на этот репозиторий и команды воспроизведения. Последнюю командную версию отправить в GitHub и нажать «Сдать решение» на платформе хакатона; публикация коммитов не заменяет сдачу на платформе.

Короткое объяснение решения для защиты: «Сначала код исключает неподходящих и занятых подрядчиков, затем по фиксированной формуле выбирает до трёх. Объяснения строятся только по фактам этих карточек и показывают их различия. Кэш сохраняет одинаковый текст при повторе запроса, а при задержке или ошибке модели сервис возвращает проверяемое объяснение из фактов. Пустую выдачу мы показываем с причинами и подсказками».

## Данные и ограничения

Датасет организаторов: 66 анонимизированных профилей, 17 категорий, включая 13 полностью синтетических записей. Исходный CSV не меняется. AI сохраняет `flags.synthetic`, `flags.priceImputed`, `flags.cityImputed` и явно отмечает синтетику и оценочные цены в тексте. Движок поддерживает необязательный `data/synthetic.csv`.

- Свободная дата означает отсутствие занятости в предоставленном календаре, а не подтверждённую бронь. Цена «от» не гарантирует итоговую смету.
- Описания являются заявлениями профилей; независимой проверки опыта, качества и отзывов нет.
- При одинаковых переданных фактах нельзя честно придумать различия. Модуль не присваивает вымышленных преимуществ.
- Повторяемость LLM-текста после перезапуска требует сохранённого файлового кэша. При недоступном файле используется память процесса; после удаления кэша генерация может отличаться даже при `temperature=0`.
- Кэш рассчитан на один Node.js-процесс, многопроцессная синхронизация не реализована.
- Ориентир до 10 секунд относится к пользовательскому сценарию: помимо серверного предела 9 секунд влияют сеть, диск и загрузка процесса.
- Избранное хранится только в localStorage этого браузера. Нет бронирования, контактов, уведомлений, аккаунтов и публичного развёртывания.
- Фото сервировки в боковой панели служит иллюстрацией сезона, не изображает конкретного подрядчика. Источник указан в `public/assets/README.md`; профили обозначены инициалами.
