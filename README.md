# pITchers: умный подбор подрядчиков

HackAlem AI, трек «Креативные индустрии», кейс #79-lite.

Заказчик уже выбрал город и формат мероприятия, но в каталоге слишком много вариантов. Сервис принимает параметры заказа, выбирает до трёх доступных подрядчиков и объясняет каждый выбор конкретными фактами. Ценность решения: сократить время выбора, показать различия кандидатов и понятные причины пустой выдачи.

## Что реализовано

- Загрузка 66 профилей из CSV в память, нормализация цен, форматов, языков, календарей и флагов.
- Детерминированные фильтры и ранжирование; занятые на выбранную дату профили исключаются.
- Статусы `found` (3 карточки), `partial` (1–2), `no_category`, `all_filtered`; причины отсева, другие города, подсказки по дате и бюджету.
- `explain(result)`: один запрос к LLM для всех карточек, два предложения на русском из фактов движка.
- Резервные объяснения без сети, таймаут 6 секунд с отменой запроса, отключённые повторы API, файловый кэш.
- Автоматические тесты и консольная демонстрация для жюри.

Готовы ядро и AI-модуль. HTTP-сервер `src/server.js` и интерфейс `public/` пока не реализованы. Демонстрация запускается через CLI; `npm start` пока не поднимает сайт. Публичной развёрнутой версии нет.

## Сценарий и архитектура

Вход: `city`, `date` (YYYY-MM-DD), `eventType`, `category`, `budget`; опционально `hours` и `language`. Даты допустимы только с `2026-09-23` по `2026-12-31`.

```text
CSV -> нормализация -> город/категория -> жёсткие фильтры
    -> детерминированные баллы -> первые 3 + факты
    -> кэш / LLM с таймаутом / резервные объяснения -> EngineResult
```

Фильтры идут в порядке: занятость, бюджет, формат, язык, часы. Каждый исключённый профиль учитывается по первой причине. Ранжирование: релевантность описания 35%, запас бюджета 25%, специализация 15%, часы 15%, качество данных 10%. Балл округляется до четырёх знаков; при равенстве порядок определяется `id`.

Выход сохраняет `EngineResult`: `status`, `query`, `candidatesTotal`, `excluded`, `cards`, `otherCities`, `hints`, `message`. AI добавляет карточкам только `explanation` и `explanationSource`: `llm`, `template` или `cache`. Имена, цены, баллы, сообщения и порядок не меняются.

LLM получает только запрос, ID и факты карточек, а также обязательные фразы, вычисленные из этих фактов. Имена и баллы не передаются. Второе предложение должно содержать конкретную деталь и доступное отличие: например, больший лимит часов, меньшую начальную цену или фрагмент описания. Если сравнительного отличия нет, модуль использует деталь профиля и не выдумывает уникальность.

Проверяются JSON, точное множество ID, длина, числовые факты, дата, цена, формат, язык, обязательные детали и маркировка синтетики/оценочных цен. Невалидный, неполный или оборванный ответ заменяется локальными объяснениями для всех карточек. Это не полная семантическая проверка каждого слова модели.

Ключ кэша: SHA-256 от JSON запроса, упорядоченных ID и модели; порядок ключей объектов нормализуется. Отдельный отпечаток фактов, endpoint и промпта защищает от устаревших текстов. Сохраняются также резервные объяснения: восстановление API не меняет уже выданный текст. Одновременные одинаковые запросы в одном экземпляре используют общий вызов LLM.

## Стек и структура

Node.js 24, ES modules, `csv-parse`, `dotenv`, официальный SDK `openai`. В командном `package.json` также подключён Express для будущего API. Тесты используют встроенный `node:test`. Базы данных и дообучения нет.

## Установка

Откройте репозиторий в VS Code и выполните в терминале:

```powershell
node --version
npm ci
node src/engine/data.js
```

Для офлайн-демо ключ не нужен. Для LLM создайте личный `.env` в корне:

```dotenv
LLM_API_KEY=your-own-key
LLM_BASE_URL=
LLM_MODEL=gpt-4o-mini
PORT=3000
```

Выберите модель, доступную в своём аккаунте. `LLM_BASE_URL` пуст для стандартного OpenAI API; для NVIDIA по командной конфигурации: `https://integrate.api.nvidia.com/v1`. При смене провайдера нужны его ключ и модель с поддержкой Chat Completions, JSON-ответов и `temperature=0`. Работоспособность конкретной NVIDIA-модели отдельно не подтверждена.

Поддержаны резервные имена `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`, если `LLM_*` не заданы. Само наличие `NVIDIA_API_KEY` не переключает провайдера. Ключ используется приложением; расширение VS Code для API не требуется. `.env`, `node_modules` и `.cache` не коммитятся.

Официальная справка: [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [JSON-ответы](https://developers.openai.com/api/docs/guides/structured-outputs).

## Проверка для жюри

```powershell
node --test src/ai/explain.test.js
node src/ai/demo.js
npm run demo
```

Первая команда проверяет AI без сети и оплаты API. Вторая показывает движок с резервными объяснениями. Третья запускает командное демо только движка.

| Сценарий | Город, категория, дата | Формат и бюджет |
| --- | --- | --- |
| Плотная категория | Алматы, Ведущий, 17.10.2026 | корпоратив, 1 500 000 ₸ |
| Другая дата | Алматы, Ведущий, 26.12.2026 | корпоратив, 1 500 000 ₸ |
| Редкая категория | Алматы, Флорист, 17.10.2026 | свадьба, 500 000 ₸ |
| Категории нет | Астана, Декоратор, 17.10.2026 | корпоратив, 1 500 000 ₸ |
| Все отфильтрованы | Алматы, Ведущий, 25.12.2026 | корпоратив, 100 000 ₸ |

`src/ai/demo.js` повторяет каждый запрос и проверяет совпадение ID и текстов. Тесты дополнительно проверяют различимость объяснений после удаления имён, занятость, флаги, сохранение полей движка, единый LLM-вызов, таймаут с отменой, повреждённый кэш, ошибки API и повторяемость после создания нового экземпляра.

Реальный вызов настроенного провайдера:

```powershell
node src/ai/demo.js --live
```

Офлайн-демо использует отдельное имя модели `offline-template` в ключе кэша и не подменяет live-демо сохранёнными шаблонами. `explanationSource: llm` подтверждает принятый ответ модели, `template` означает резервный путь, `cache` означает повтор сохранённого текста. В live-демо выводятся причины резерва (`authentication`, `timeout`, `invalid_response`, `api_error`, `no_api_key`) без ключей и тела ошибок. Успешная выдача карточек сама по себе не подтверждает подключение LLM.

## Подключение к серверу

Участнику 3 достаточно вызвать:

```js
import { recommend } from "./engine/recommend.js";
import { explain } from "./ai/explain.js";

const query = {
  city: "Алматы", date: "2026-10-17", eventType: "корпоратив",
  category: "Ведущий", budget: 1500000,
};
const result = await explain(recommend(query));
```

Сервер отвечает за валидационные HTTP-ошибки движка и добавление `elapsedMs`. AI-модуль не меняет `message` и не создаёт новых статусов. Для тестов доступны `createExplainer({ client, cache, timeoutMs, onFallback })` и `createCache({ filePath })`; `filePath: null` включает кэш только в памяти. Таймаут не может превышать 6 секунд.

## Данные и ограничения

Датасет организаторов: 66 анонимизированных профилей, 17 категорий, включая 13 полностью синтетических записей. Исходный CSV не меняется. AI сохраняет `flags.synthetic`, `flags.priceImputed`, `flags.cityImputed` и явно отмечает синтетику и оценочные цены в тексте. Движок поддерживает необязательный `data/synthetic.csv`.

- Свободная дата означает отсутствие занятости в предоставленном календаре, а не подтверждённую бронь. Цена «от» не гарантирует итоговую смету.
- Описания являются заявлениями профилей; независимой проверки опыта, качества и отзывов нет.
- При одинаковых переданных фактах нельзя честно придумать различия. Модуль не присваивает вымышленных преимуществ.
- Повторяемость LLM-текста после перезапуска требует сохранённого файлового кэша. При недоступном файле используется память процесса; после удаления кэша генерация может отличаться даже при `temperature=0`.
- Кэш рассчитан на один Node.js-процесс, многопроцессная синхронизация не реализована.
- Ориентир до 10 секунд относится к пользовательскому сценарию: помимо 6-секундного таймаута LLM на него влияют задержки диска и загруженность процесса.
- Нет бронирования, уведомлений, пользовательских аккаунтов и публичного развёртывания. Сервер и UI остаются задачей участника 3.
