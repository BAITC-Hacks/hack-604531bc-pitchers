# Объяснения и подготовка демо

Все команды выполняются из корня репозитория. Нужны Node.js 24 и зависимости из `npm ci`.
Этот README находится в `src/ai/`, поскольку текущие коммиты ограничены этой папкой и `scripts/blind-test.js`.

## Перед показом

В локальном `.env` задайте собственный `LLM_API_KEY`, `LLM_MODEL=gpt-4o-mini` и при необходимости
`LLM_BASE_URL`. Также поддерживаются `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL`;
приоритет у переменных `LLM_*`. Ключи и `.cache` не коммитятся.
Модель по умолчанию: [GPT-4o mini](https://developers.openai.com/api/docs/models/gpt-4o-mini).

```sh
node src/ai/warm-cache.js --refresh
node src/ai/warm-cache.js --check
node scripts/blind-test.js --live
```

`--refresh` заново вызывает модель для каждого непустого сценария, даже если кэш уже есть.
Без флага действующие проверенные записи переиспользуются. `--check` не вызывает API:
проверяет готовность сохранённых ответов. Не используйте `--check` вместе с `--refresh`.
После прогрева запустите или перезапустите `npm start`, чтобы процесс сервера прочитал свежий файловый кэш.

Прогрев использует пять запросов из `scenarios.js`, общих для обычного и слепого демо:

| Сценарий | Дата | Запрос | Ожидаемая выдача |
| --- | --- | --- | --- |
| Плотная категория | 17.10.2026 | Алматы, ведущий, корпоратив, 1 500 000 ₸ | 3 карточки |
| Другая дата | 26.12.2026 | Те же условия | 1 карточка |
| Редкая категория | 17.10.2026 | Алматы, флорист, свадьба, 500 000 ₸ | 1 синтетическая карточка |
| Нет категории | 17.10.2026 | Астана, декоратор, корпоратив, 1 500 000 ₸ | Нет категории |
| Все отфильтрованы | 25.12.2026 | Алматы, ведущий, корпоратив, 100 000 ₸ | Причины отсева |

Два пустых результата проходят движок, но не требуют LLM: нечего объяснять.
Успех прогрева: `Готово с LLM-кэшем: 3; без карточек: 2; не готово: 0; всего: 5`.
Каждая непустая запись проверяется новым читателем кэша с отключённым API.
При таймауте, ошибке ключа, невалидном тексте или невозможности записать файл скрипт завершится с кодом 1.
`authentication` означает ошибку авторизации: проверьте свою пару ключ/адрес провайдера.
Шаблон не считается успешным прогревом. Наличие работающего ключа само по себе не доказывает готовность.

## Слепая проверка

```sh
node scripts/blind-test.js
node scripts/blind-test.js --live
node --test src/ai/*.test.js tests/*.test.js
node src/ai/verify.js
```

Первая команда работает офлайн. Вторая использует LLM или его проверенный кэш; если получен шаблон,
она явно сообщает об этом и возвращает код 1. Вместо имён и ID выводятся A, B, C.
Имена скрываются также внутри текста, а различимость проверяется повторно уже после скрытия.
Для каждой пары у ОБЕИХ карточек должна быть собственная цифра или цитата, подтверждённая профилем
и отсутствующая у другой карточки. Цена, часы и цитаты сравниваются с фактами соседей.
Одна карточка не объявляется успешным попарным сравнением; пустые результаты показывают причины движка.

## Поведение AI

- Одна генерация на все карточки, `temperature: 0`; при невалидном JSON или объяснениях ровно одна перегенерация.
- Обе попытки вместе ограничены 8 секундами, автоматические повторы SDK отключены.
- Объяснение начинается с отличия и содержит 1–2 предложения. Дата и общий формат вынесены в `commonFacts`.
- При пустых `facts.differentiators` отличительные часы, цены и цитаты выводятся из существующих фактов всех показанных карточек. Движок и его порядок не меняются.
- Резервный шаблон тоже начинается с отличия. Синтетичность и оценочность цены остаются явными.
- Кэш версии 2 содержит только проверенные ответы с `source: "llm"`. Версия включена в ключ; отпечаток фактов, промпта и провайдера защищает от устаревших записей.
- `explanationSource: "cache"` означает сохранённый LLM-ответ, никогда шаблон. Шаблоны не сохраняются даже в памяти, следующий запрос снова пробует модель.
- Одинаковый прогретый запрос даёт одинаковый текст. После временного сбоя шаблон может смениться настоящим LLM-ответом: это восстановление, а не закрепление ошибки в кэше.
- Для фактически одинаковых профилей, например `HK-23752` и `HK-83709`, нельзя честно придумать уникальную цифру или цитату. Шаблон сообщает об отсутствии подтверждённых различий; такой ответ не проходит LLM-кэширование.

## Интеграция с сайтом

В `src/server.js` и интерфейсе выполнены интеграционные правки:

1. Внешний предел `withExplanations` увеличен до 9000 мс. Ответ AI на 7,5 секунде больше не обрывается сервером; это проверяется тестом с виртуальными часами. При внешнем таймауте используется тот же фактологический шаблон, что и в AI-модуле.
2. Сервер и AI сохраняют `commonFacts` движка, интерфейс показывает их один раз над карточками. HTTP-проверка проверяет сохранение этого поля.

Формат поля: массив строк на русском, пустой массив при отсутствии карточек. Для совместимости с предыдущим движком AI также принимает результат без этого поля и формирует объект `{ city, date, eventType, language?, hours?, text }`; интерфейс и консольные скрипты поддерживают оба формата.
Сайт запускается командой `npm start`, а режим без внешних вызовов с автоматическим выбором свободного порта: `npm run preview`.
`npm run test:ui` проверяет браузерные сценарии на десктопе и телефоне без обращения к LLM.
